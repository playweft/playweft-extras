# 绒绒消消乐 · Fuzzy Match 3

动物主题单人三消。直接打开 `/fuzzy-match-3/` 游玩，或通过 Playweft 的单人模式打开。

游戏主体、弹窗及玩法说明使用 Fredoka（数字、英文）与站酷快乐体（中文），顶栏和导航保留系统字体。两款字体均为随游戏分发的本地 WOFF2，不依赖外部字体服务。字体文件、完整 OFL 1.1 许可证及来源记录位于 `public/fuzzy-match-3/fonts/`；保留原字体全部字符，未覆盖字符回退到系统字体。

- 规则层 `game.js` 和 AI 只使用数字棋子类型、`TYPE_COUNT` 与收集目标 `targetType`；动物名称与标识集中在展示层 `theme.js`，图形和配色在 `art.jsx`，不参与匹配、计分或难度计算。
- 六种动物棋子：淡黄柴犬、偏红橙虎、紫色鸟、浅棕熊、蓝牛、草绿龙；通过耳朵、喙、角、脸型与配色共同区分。
- 8 × 8 浅网格棋盘，点选、滑动或键盘交换相邻棋子。交换有移动动画，无效交换原路返回、不扣步数。
- 下落动画使用统一节拍，同列连续棋子保持一格间距，新棋子按空位释放顺序从顶行进入；斜落路径也按同一时间轴避让占用格。
- 横向四连产生纵向条纹，纵向四连产生横向条纹；与普通棋子交换仍须形成消除。同方向条纹命中另一颗条纹时，后者转为垂直于来袭方向的消除；异方向命中保持原方向，每颗条纹每轮只触发一次。双条纹交换不受原本方向影响，横向交换清除一行两列，纵向交换清除两行一列。
- 五连及十字、T / L 形交叉消除产生彩虹道具：与普通棋子交换消除同色棋子；与条纹交换将全部同色棋子变为随机行或列条纹后一起引爆，这批条纹按各自随机生成的方向消除，不因同向条纹扫过而改向；两个彩虹交换时，先选中的彩虹清除当前屏的其他棋子，另一个保留并加入引爆队列，补盘后优先消除最多的一种棋子；未参与交换的彩虹在全屏消除时保留。
- 彩虹与普通或条纹棋子交换时，若换入棋子形成四连、五连或交叉图案，原效果照常触发，并在该棋子落点生成对应的条纹或彩虹。原条纹仍参与转换和引爆，新道具本轮保留，不会被同一轮效果立即消耗；该保留格按转换前的动物种类计入收集目标与累计消除，并计入基础分和面积倍率。普通四连收集 4 个、五连收集 5 个，更长直线及交叉图案按匹配格数去重计数。
- 条纹扫中彩虹时，先保留并标记彩虹，补充棋盘后自动消除当前数量最多的一种棋子。待触发彩虹优先于普通三消，每次补充只触发一颗；其他已标记彩虹保留，下一次补充再按新盘面选择最多的棋子，随后恢复普通连消。数量相同时按棋子类型顺序选择；冻结棋子仍按破冰规则处理。掉落会携带标记，恢复存档会继续处理待触发效果，不额外扣步数。
- 所有关卡按 `(level - 1) % 4` 轮换四类主目标：收集指定棋子、扩散地板颜色、揭开隐藏图案、护送目标到底部。挑战关仍为第 10 关起的 5 的倍数；由于 `5 % 4 = 1`，挑战目标依次为涂色、揭图、护送、收集，每 20 关重复，所有相邻关卡均不同类型。每组四个普通关包含全部类型，顺序随组轮换。收集挑战仍收集 36 个；每日挑战固定收集 15 个。主目标、得分和全部解冻均满足才能过关。
- 普通涂色关从第 20 关起使用中央四格，加目标区域四角各 L 形三格，共 16 格，保持水平、垂直镜像及 90° 旋转对称；前 20 关与挑战关保留中央四格加四角共八格，避免开局涂满引导关。不设置冰块，仅向本轮连通的匹配或道具效果所覆盖的目标地板扩散，不会把另一组无关匹配一起涂色。条纹仅从引爆位置传播颜色，消除路径经过染色格不会反向取色；匹配或上游染色效果先染到条纹所在格后，可继续沿条纹传播，双条纹的十字消除也遵循此规则。彩虹与条纹交换时，仅按交换前两个位置的染色状态给整批转换条纹取色：任一位置已染色则转换格及其爆炸路径传播染色；否则远处的同类棋子、转换条纹或同轮新染色都不会给整批取色。前 20 关标记中央 4×4 地板，第 20–99 关为 6×6，第 100 关起为全盘。地板与隐藏图案按棋盘坐标保存，交换、下落和重排不会移动它们；生成奖励道具的转换格也算命中，冰层吸收的命中不算。
- 揭图需要清除完整的 2×2 遮挡区，每幅图四格全部揭开才计数；普通关前 20 关两幅，以后三幅；揭图挑战关在第 100 关前四幅（16 格），第 100 关起五幅（20 格）。护送关最多设置两格单层冰，普通关的两格冰内分别封住横向、纵向条纹，挑战关仍为普通棋子；护送目标前 100 关共两个，第 100 关起共三个，同时在盘上最多两个，送达后再从第一排补充后备目标，不替换冰块；蛋随重力下落，可以通过合法匹配交换移动，不匹配、不被爆炸消除，也不会被重排移动。落到最底行后收集，再补盘和继续连消。主题图案和名称仅在展示层定义，引擎使用通用的下落目标类型。
- 目标数据由 `objectives.js` 统一维护，AI 和动画结算使用相同的推进规则。旧存档缺少目标字段时一次性补成收集目标，保留当前局全部进度；后续新局按轮换规则生成。支持连消倍率、提示、重排和自动解锁死盘。
- 当前连消结束后，只有达成通关目标才进入终局清场：所有条纹按各自原方向同时引爆，彼此命中不翻转；所有彩虹标记为待引爆，按既有队列规则每次补盘只触发一颗、优先于普通匹配。清场中新生成的道具也继续处理，直到棋盘没有特殊道具。冰封道具先逐层解冻再触发。步数耗尽但未达标时，只结算本次交换的正常连消及其已触发道具，不额外引爆剩余道具。终局清场从 1 倍连消开始，不扣步数，得分、收集和解冻照常计入；仅标记彩虹不计分、不增加连消倍率，每波消除同步更新得分、星级进度和收集目标，最后统一判定胜负、折算剩余步数并保存最高星数；动画中的分数仅用于展示，不提前写入未稳定棋盘的存档。
- 四连每组额外奖励 80 分，五连或 L / T / 十字等交叉图案每组额外奖励 200 分，同组只取最高一档，后续连消可再次获得；图案奖励不乘面积或连消倍率，多组独立图案分别获得奖励。首轮普通三连 180 分、四连 350 分、五连或五颗交叉图案 550 分。面积倍率为 `1 + sqrt(clamp((计分格数 - 3) / (64 - 3), 0, 1))`，采用上凸平方根曲线，初段增长较快、后段逐渐放缓，3 格及以下为 1 倍，64 格为 2 倍，计分格数为实际移除格加上本轮生成道具的格数，重复命中去重；生成道具的格子计入基础分和面积倍率，冰层保留格不计入。得分为 `四舍五入到十位(计分格数 × 60 × 面积倍率 × 连消倍率) + 图案奖励`，图案奖励不乘面积或连消倍率。两组三连首轮 440 分，第二轮两组三连 880 分，合计 1,320 分；首轮消除 40 格为 4,270 分，64 格为 7,680 分（均未包含固定奖励）。
- 每次有效交换的正常连消结束后，分数与连击文字收起，再显示一条表扬动画：3 连击或本步累计 1,500 分为 `Great!`，4 连击或 3,500 分为 `Excellent!`，5 连击或 7,000 分为 `Perfect!`，按达到的最高档显示一次。仅为视觉反馈，不额外加分、不播放语音；自动尾盘清场、剩余步数奖励及读档恢复不参与档位判定。文字显示约 1 秒，普通回合不阻挡继续操作，下一次交换、切换关卡或模式会立即收起；结算框等文字结束后再出现。减少动态效果时不播放位移动画，文字仍保留正常阅读时间。
- 第 4 关开始出现冰封格子，逐渐增加到 8 格、最多 3 格双层冰。冻结棋子不能交换或下落；相邻棋子消除、匹配格生成条纹或彩虹、或道具直接命中时，每个消除波次最多减一层，冰层保护棋子免于此次消除。重排保留冻结棋子的位置与冰层，全部解冻也是过关目标。
- 补充时，上方通畅的空位始终由正上方垂直补入，等待顶行的新棋子落下；只要正上方仍有可补充的通路，即使暂时为空也等待直落；正上方补充通路完全被冰块切断时才从斜上方补入。例如顶行单个冰块下的一整列清空时，只有冰块下第一格斜补，再从该格逐个直落。横排冰块下方会留下逐层收窄的三角空区，而不是整列空缺。新棋子只从未封冻的顶行进入。被冰块完全封住的空位会保留，解冻后才继续补入。空位不能交换、不参与计分，重排和存档保留这些空位。
- 两侧可补入时，斜落按左、右交替；一侧被冰块或边界封住时只用另一侧。轮换由同列上方最近的冰块记录，跨连消、回合和存档保留，冰块彻底解冻后清除。轮到的一侧暂时缺棋子但通路仍开放时，等待上方补充，不跳回另一侧；完全无路补入时保留空位。
- 开局步数按关卡基础步数、冰层数量和相邻冰格密度配置，每 3 个冰层或相邻冰格对向上取整增加 1 步；局中不暗改步数。旧存档保留原来的棋盘和剩余步数，不会补入冰块。
- 仅通关后将剩余步数按每步 1,500 分折算为奖励。最终得分和最高分包含奖励，存档中的 `score` 保留消除分数，奖励由通关状态和剩余步数推导，刷新不会重复加分。
- 一星与过关分数在原配置基础上下调约 20%（基础分系数从 1.2 改为 0.96），向上取为 100 的整数倍。通关分数仍要求实际消除得分达到门槛，不能提前用剩余步数奖励抵扣；通关后按最终总分评星。二星取一星与三星的中点，四舍五入到 100。第一关为 1,800 / 5,800 / 9,800 分，每日挑战为 2,900 / 7,000 / 11,000 分。三星门槛保持不变，高连消得分或高效通关均可获得三星。
- 闯关三星采用两段曲线：前四关为引导段，三星分数依次为 9,800 / 16,000 / 22,300 / 28,500；第二段从第 4 关的 28,500 分逐渐放缓增长，第 1,000 关锚点为 35,000 分，后续自然延拓，第 10,000 关为 35,200 分。三星率的历史校准与当前规则测算见下方。
- 基础步数、普通收集数量与冰层预算随进度变化；普通收集最多 24 个，冰层预算最多 11 层，涂色与护送按各自规则减冰，保留预算补偿的步数。第 1,000 关分数门槛为 14,400 / 24,700 / 35,000，曲线继续缓慢延拓，第 10,000 关为 14,800 / 25,000 / 35,200。所有分数目标均为 100 的整数倍，棋子类型与冰封布局继续轮换，密集冰块按布局额外补偿步数。
- 从第 10 关起，关数为 5 的倍数时为挑战关，目标按四类轮换，仅收集类型使用 36 个目标棋子的要求；揭图挑战在第 100 关前需揭开四幅、第 100 关起五幅图案，涂色与护送挑战沿用各自现有目标参数，每日挑战仍收集 15 个。目标要求固定，局中不动态调整；三星分数门槛沿用两段曲线。已保存对局保留原目标，重玩或新开关卡按新轮换生成。
- 连续有效失败后的补盘帮助按 15% / 13.5% / 12% / 11% / 10% 五档降低一种数字棋子类型的实际生成概率，其余五种均分剩余概率；首局均为 1/6。步数耗尽失败，或至少消耗初始步数的 60%（向上取整、且不少于八步）后主动重开，才累计一次。同一局只记一次，快速重开、返回选关和切换模式不升级也不清空；同关固定同一种被降低的类型，收集目标类型排除，档位在下一局启用，本局内不变化。通关清除本关帮助。只调整普通补盘，开局、任务物件生成及重排规则保留；AI 的预测补盘使用同样的分布。
- 存档保存每局的初始步数及当前帮助档位，另以 `retryHelp` 保存少量失败计数和类型，不为每个重试关卡额外保存棋盘；旧存档补齐初始步数，旧失败终局只登记一次。每日记录按日期独立且会清理过期记录，普通闯关和重玩共享同关记录。
- 闯关、每日挑战分别保留进度。每日挑战使用本地日期种子生成同一初始棋盘，后续掉落随机。
- 暂停菜单可「返回选关」，查看每关最高星数并重玩已解锁关卡，每页显示 40 关。重玩不会覆盖最新闯关进度，较低星数不会覆盖历史纪录；打开游戏仍直接恢复最新闯关存档。旧存档沿用当前关卡解锁进度，已保存的通关关卡可补记星级，其他历史星级从更新后开始记录。
- 平台内通过 `localStorage.*` bridge 保存到平台侧 IndexedDB，独立打开时保存到游戏自己的 IndexedDB，均为异步本地存档；旧 localStorage 数据在目标为空时一次性迁移，确认提交后再清理来源。存档键为 `playweft:fuzzy-match-3:v1`；兼容读取旧键 `playweft:fruit-isle:v1`，成功写入新键后删除旧键，写入失败时保留旧存档。新旧键同时存在时优先使用新键；累计消除数迁移至 `stats.eliminated`，旧字段 `stats.fruit` 仅用于迁移，写入时只保留新字段；旧道具和缺失字段也转换到当前格式，重新打开仅读取迁移后的新存档。不联网同步。
- 棋盘外采用青蓝渐变、浅色文字与暖金进度。侧栏和手机底栏仅在选关列表显示，关卡内移除导航占位并居中棋盘；从选关打开设置、统计或说明后仍返回选关。桌面保留无边框的半透明卡片与目标面板，手机保持平面布局。仅为应用式响应布局，没有 Service Worker 或 Web App Manifest。

`game.js` 维护独立规则，`assistance.js` 定义重试资格、失败计数和补盘权重，`objectives.js` 维护目标轮换、进度和存档校验；`falling.js` 将实际下落路径排成统一动画时间轴；`feedback.js` 定义纯展示的表扬档位；`app.jsx` 维护交互、动画、存储和音效；`art.jsx` 绘制本地 SVG 动物头像与冰层，界面图标使用 `lucide-preact` 并随游戏打包。没有外部字体、图片或运行时网络依赖请求。

npm run dev
npm run check

离线校准使用 `scripts/fuzzy-match-3-balance.mjs`，直接调用游戏规则，不使用提示或重排道具。三星率按全部对局统计，包含失败局，这是指定策略的模拟结果，不代表真人通关率。

- `simple`：优先首轮得分。
- `medium`：再考虑当前主目标、破冰和生成道具；护送目标同时评估下方消除和下落距离。
- `strong`（默认）：保留四个候选，各抽样三个独立的掉落局面，搜索两步，评估目标进度、冻结阻挡、道具相邻组合、过关和最终星级。生成道具时也比较两个交换方向。预测与实际掉落使用独立的随机数流，不能预知实际掉落。

```sh
node scripts/fuzzy-match-3-balance.mjs --level 1000 --games 1000 --seed 50001 --strategy strong
node scripts/fuzzy-match-3-balance.mjs --level 1000 --games 1000 --seed 50001 --strategy medium
```
